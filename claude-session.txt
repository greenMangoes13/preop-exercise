     Context

     Branch emma-solution, clean tree; DESIGN.md committed in f83fbeb. Goal:
     replace the naive one-call
     triage_submission in core.py with "LLM extracts grounded facts → code
     applies Rules 1–4". run_evals.py
     scores decision + exact issue-category set + schema validity, with equal
     weights.
     Naive baseline (already run): 70.0% aggregate; determinism 100% decision 
     stability, 10% exact output match.

     Agreed decisions

     - Rename the existing function to baseline_triage_submission. The 3
       existing tests point at it unchanged, and the new triage_submission gets
       its own tests.
     - Use a lazy, resettable OpenAI client so the test fixture still works.
     - The scored TriageOutput is purely code-derived. Quotes, tokens, latency,
       and extracted facts go to the data/extractions.jsonl sidecar, which is
       gitignored.
     - Every issue still carries sources that point to the exact record. Each
       source has kind (doc/lab/vital/med/procedure), id (doc_id or lab id),
       type, date, and the normalized value, e.g. "CBC 2026-02-10, 19d before 
       procedure" or "BP 157/117". Every check in checks[] carries the same
       source.
     - Unknown or ungrounded facts fail the rule's own category: missing
       H&P/consent → REQUIRED_DOCUMENTATION, missing CBC/CMP → REQUIRED_TESTING.
       Only unknown anticoag status, missing BP/temp, or null procedure
       date/risk → MISSING_REQUIRED_DATA.
     - Null procedure date/risk: skip the date/risk-dependent rules (H&P window,
       lab windows). Consent, anticoag, and vitals are still evaluated.

     Step 0: preserve the naive results (no API calls)

     cp data/baseline_outputs.jsonl data/naive_outputs.jsonl
     cp data/eval_report.json data/naive_report.json
     cp data/determinism_report.json data/naive_determinism_report.json

     Step 1: rules.py + tests/test_rules.py (pure, no API). STOP for review 
     after this step.

     - The input types live in rules.py for now: Pydantic models for normalized
       records and grounded facts, each carrying its source pointer.
       normalize.py and extract.py will later produce these types. Types:
       - Source
       - HPFact, ConsentFact
       - LabRecord
       - VitalReading (BP/temp, °F, date, order-in-note)
       - AnticoagEvidence (med-list status + note mentions)
       - AnticoagPlan
       - CaseFacts (procedure date/risk + all of the above)
     - evaluate(facts: CaseFacts) -> TriageResult returns decision, issues
       (category, rule, evidence, sources), checks, and a code-built
       explanation.
     - Rules:
       - H&P: pre-op only; 0 ≤ days_before ≤ 30.
       - Consent: any signed consent that matches the scheduled procedure.
       - Labs: drop entered-in-error, then take the latest per required test; 0 
         ≤ days ≤ 30 (LOW/MOD CBC) or 14 (HIGH CBC+CMP).
       - Anticoag:
         - active = med-list active, or a note says current.
         - Med-list active=False plus a note saying stopped → not active.
         - Med-list active=None with no confirming note → MISSING_REQUIRED_DATA.
         - A plan passes only if the drug matches, it has both pre- and post-op
           instructions, and it is not deferred to another team.
       - Vitals:
         - Take the latest reading per type. When both readings have full
           timestamps, compare the timestamps; within one note, later order wins
           (recheck).
         - Fall back to "note reading wins" only when a same-day note reading
           has a date but no time. A structured recheck timed later that day
           beats an earlier timed note reading.
         - Test: a structured reading at 15:00 beats a 09:00 note reading on the
           same day, and an untimed note reading beats a same-day structured
           reading.
         - SBP ≥ 180, DBP ≥ 110, or T > 100.4 → ACUTE_SAFETY_EXCLUSION.
         - No BP or no temp → MISSING_REQUIRED_DATA.
       - Precedence: NOT_CLEARED > NEEDS_FOLLOW_UP > READY, and all issues are
         reported.
     - Tests use hand-built CaseFacts that mirror labeled cases:
       - 00002 (°C fever + unsigned consent → NOT_CLEARED with 2 categories)
       - 00004 (entered-in-error fallback)
       - 00009 (CBC 15d HIGH + no temp)
       - 00018 (plan for the wrong drug)
       - 00019 (inactive warfarin → READY)

  whether the patient is ready for surgery; separate code applies the policy to
  what you extract.

  Rules for every fact:
  - doc_id: the id of the document the fact comes from, copied exactly.
  - quote: a short excerpt (one line or sentence, at most 200 characters) copied
  character-for-character from that document's text. Do not paraphrase,
  abbreviate, fix typos, or join text from different places. Facts whose quote
  is not found in that document are discarded.
  - Extract only what the documents state. Never fill gaps from general
  knowledge. When a document is ambiguous, use the "unclear"/"unknown"/null
  option.

  What to extract:

  1. hp_candidates: every document that is itself a history and physical (H&P),
  whatever its title or spelling ("H&P", "History and Physical", "Admission
  H&P", "Clinic H&P", "Pre-op H and P", ...).
     - is_preop_hp: true if it is an evaluation for a planned surgery; false if
  it is an annual wellness, establish-care, or other visit not done to evaluate
  for surgery.
     - quote: the line showing the encounter's purpose (e.g. "Encounter: annual
  wellness / establish care", or "Planned procedure: ...").
     Do not list documents that only refer to an H&P (e.g. "H&P reviewed", "H&P
  not on file").

  2. consents: every surgical consent document.
     - signed: "true" only if the text shows the patient signed (patient
  signature, patient e-signature, "Signed by patient", "Patient signature on
  file - signed"). "false" if it shows the patient has not signed (blank

     - procedure_named: the procedure as written in the consent, or null.
     - matches_scheduled_procedure: "yes" if procedure_named is the same

  Design choices to check

  1. Dates come from code, never the model. H&P, consent and note-vital dates
